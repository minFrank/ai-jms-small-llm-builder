## 坑二:脚本找错了录音文件(原始报错)

**原始报错(逐字)**:
```
LibsndfileError: Error opening 'C:\Users\Frank\AppData\Roaming\OmniVoice\engines\cosyvoice\CosyVoice\我的录音.wav': System error.
```

原因:脚本先把工作目录切到了模型目录,再去读相对路径 `我的录音.wav` ——
于是它去模型目录里找读者的录音,当然找不到。

修法:`tools/tts.py` 里把 `--voice` / `--text-file` / `--out` 三个路径**在 chdir 之前**转成绝对路径。

## 坑三:中文变量把命令行拆坏(原始报错)

**原始报错(逐字)**:
```
usage: tts.py [-h] --text-file TEXT_FILE --voice VOICE --voice-text VOICE_TEXT
              --out OUT [--model-dir MODEL_DIR]
tts.py: error: the following arguments are required: --out
```

**为什么这条特别值钱**:命令行里明明写了 `--out`,Python 却说它不存在 ——
因为录音文本是经 Windows 批处理的中文变量 `%VOICETEXT%` 传进命令行的,
在 `chcp 65001` 的代码页下,展开后的中文把命令拆坏了。

修法:不再让批处理传中文,改成 **`--voice-text-file`,由 Python 自己读那个文本文件**。

