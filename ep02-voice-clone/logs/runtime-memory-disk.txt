# 第 02 期 · 内存与磁盘占用实测

补测目的:审查时发现文章里的「内存 6.0–6.5G」「体积 7.1G」**没有日志依据**。这里补齐。

机器:AMD Ryzen 7 5700G(8 核 16 线程)/ 27.9G 内存 / **无独立显卡** / Windows 11

---

## ① 磁盘占用

方法:对整个 CosyVoice 目录递归统计文件大小。

```
  .venv                        1927.0 MB  (1.88 GB)   ← 运行环境
  pretrained_models            5175.6 MB  (5.05 GB)   ← 模型权重
  其余(源码等)                     约 4 MB
  ──────────────────────────────────────────
  合计                         7106.6 MB  (6.94 GB)
```

**结论:装机占用 6.94 GB**(文章写"约 7G / 模型 5.1G + 环境 2.0G"与此吻合)。

---

## ② 内存占用

方法:跑一次合成,每 3 秒采样一次「这台机器上**所有 python 进程**的内存之和」,取峰值。

⚠️ **为什么要采样"所有 python":这台机器上跑着别的东西,其中也包括 python。**
所以下面同时给出基线和净值 —— 只看总数会把别的程序算进来。

```
基线(跑之前,机器上已有的 python 进程合计):     756 MB
采样稳定平台(合成过程中的持续占用):       6800 → 7230 MB
峰值(模型加载那一瞬间):                        9007 MB
跑完之后(只剩基线):                             786 MB
```

**怎么读这三个数**:

| 指标 | 原始值 | 扣掉基线后 | 含义 |
|---|---|---|---|
| 稳定运行占用 | 6800–7230 MB | **6.0–6.5 GB** | 平时吃多少 |
| 加载瞬时峰值 | 9007 MB | **约 8.25 GB** | 加载模型那几秒的最高点 |

**结论**:
- 平时占用 **6.0–6.5 GB**
- 加载模型瞬间冲到 **约 8.25 GB**(这是净增量,不含机器上其他程序)
- → **16G 内存的机器够用**;**8G 会在加载那一步撑不住**

> **第一次采样失败的记录(留作教训)**:最初我用 `Start-Process -PassThru` 拿进程对象再读它的内存,
> 结果一直显示 **5 MB** —— 因为拿到的是包装进程,真正干活的是它的子进程。
> 那组数据已作废,不在此文件中保留;这里记一笔是为了说明:内存采样要按**进程名或路径**去采,别信 `-PassThru` 返回的那个对象。

## ③ 这两次补测的耗时(受机器负载影响,仅作参照)

```
2026-09-14 07:46  用时 245 秒(RTF 8.506)
2026-09-14 07:51  用时 232 秒(RTF 8.103)
```

同样 117 字、同样 28.8 秒成品:前四次 167–192 秒,这两次 232–245 秒(慢约 25–30%)——
因为测的时候机器**同时在跑审查任务**。

**不作为推荐值,只说明负载影响有多大。**

## ④ 模型加载时间(累计记录)

```
9 秒(第一次)  10 秒(第二次)  11 秒(第四次)  15 秒(补测①)  16 秒(补测②)
```

→ 区间 **9–16 秒**。前几次都是 9–11 秒;补测那两次偏慢,同样是因为机器在忙。


=== 文章里两个换算值的推导（供读者核对）===

1. 净增峰值 = 9007 MB（模型加载瞬间峰值）− 756 MB（跑完后的基线占用）= 8251 MB
   文章写「扣掉机器上其他程序约 8251MB」即此值。原始两个数都在上面的采样里。

2. 磁盘合计 6.94G 的构成 = 模型权重 5.05G + 运行环境 1.88G + 零散文件约 0.01G
   5.05 + 1.88 = 6.93（G），+ 0.01 = 6.94（G），与实测总占用一致。
   文章写「另有约 0.01G 是零散文件 —— 合计 6.94G」即此值。
