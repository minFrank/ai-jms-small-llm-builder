## 四轮过程

### 第一轮(2026-09-14 凌晨 · 用 hermes -z 通道)

- 结果:审查 Agent 超时;L1 抓到「数字无日志」类问题;L2/L3/校对/通读均出报告
- 报告:`round1-hermes-channel/`
- **主要发现**:大量数字**没有日志依据**(内存、体积、报错原文)—— 这是硬伤
- **处置**:补测并留档
  - `logs/runtime-memory-disk.txt` —— 磁盘 6.94G、内存峰值 9G / 稳态 6.0–6.5G
  - `logs/runtime-errors.txt` —— 三个坑的原始报错
  - 补记第五次运行(机器负载下 245 秒)

### 第二轮(改用直连 API)

- 判定:**二审 pass**;校对 block;通读 8 处困惑
- **主要发现**:
  - 通读指出我把**技术黑话**写进了给普通人的文章(「采样平台」「口径」「生成倍率」)
  - 提示读者会误读「5.8 分钟」与「167–192 秒」为矛盾
  - 「16G 起步」与「实测 6.5G」自相矛盾
- **处置**:13 项改稿

### 第三轮

- 判定:二审 pass;三审 block;通读 6 处困惑
- **主要发现**:
  - 稿件写 6.2–6.5G,日志结论是 6.0–6.5G → **数字与日志不一致**(审查 Agent + 一审同时抓到)
  - 「倍实时」读者看不懂(是快 5 倍还是慢 5 倍?)
  - 我点名的 `CC-BY-NC` / `VoiceStudio` 读者根本不认识
  - 8G 读者看完**更慌**(没给出路)
- **处置**:11 项改稿;并把被自己连带删掉的**隐私边界**与 **AI 声明**补回

### 第四轮

- 判定:二审 pass;三审 block 3 条;通读 13 处困惑
- **主要发现**:
  - 三审抓到**语义冲突**:AI 声明说"所有数据都是真的",而坑一自认"没留日志"
  - 通读问:运行环境是什么?模型是什么?微信语音为什么不行?怎么传到电脑?
  - 三审认为「9G 峰值」会让读者以为 16G 也不够
- **处置**:5 项改稿(内存说清 16G 够用、AI 声明改成"有日志的能核对/没留的直说"、运行环境与模型打比方、补微信语音说明与传文件方法)

和"9007 MB"(正确采样)—— 两份矛盾数据摆在一起会让人判定整组数据不可信。已重写日志,

同时修正:
- 峰值口径:9007 MB 是「所有 python 进程之和」,扣掉基线后**净峰值约 8.25G**(文章改「8G 出头」)

  去掉"后面会讲"的卖关子感

## 结论

**四轮累计改稿约 50 处**。其中真正的硬伤是这几类:
- **数据没有日志依据**(内存、体积、报错原文、早期那次的 15.84 秒)—— 已全部补测或如实标注
- **数字与日志不一致**(稿件写 6.2–6.5G,日志结论 6.0–6.5G)—— 已统一
- **表述会误导**(内存门槛「16G 起步」vs「实测 6.5G」;「5.8 分钟」被读成与 167–192 秒矛盾)—— 已重写
- **正文含平台不允许的导流**(GitHub 路径)—— 已弱化为纯文本备选,待定稿确认
最值钱的一条不是事实错误,而是**「作者自认为写清楚了,读者完全看不懂」** —— 这类问题自己审十遍也发现不了。
