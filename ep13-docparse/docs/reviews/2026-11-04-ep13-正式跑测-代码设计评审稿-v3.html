2. 逻辑（状态机 / 判定树 / 数据流）

2.1 CellRunner 状态机（R2-01 接线版）

INIT建 Cell 累加器 → RUNNINGn_attempt+1 → infer(timeout=1800s) → RECORDEDrep 入 reps[]；ok→n_valid+1,walls/cers 追加 → EVAL见 2.2 判定树 ↻ RUNNING未达出口且 attempt<max
EXTENDINGattempt≥8 且 n_valid≥6 且 IQR>10% → max=12 → DONE-completen_valid≥6 且 IQR 合格 | DONE-complete+unstableattempt=12 且仍超阈 | DONE-partial4≤n_valid<6 | DONE-failedfatal / n_valid<4 / median≤0 
# R2-01 接线：状态机产出的就是 schema 对象
class Cell:                      # 累加器 = schema 的生产者
    reps: list[Rep] = [];  n_attempt = 0;  n_valid = 0;  fatal = None
    def absorb(self, rep):       # 每次 attempt 恰一条
        self.reps.append(rep);  self.n_attempt += 1
        if rep.status == "ok":   # R2-01：不是 rep.ok
            self.n_valid += 1; self.walls.append(rep.wall); self.cers.append(rep.cer)
    def to_schema(self):         # fill required 19 + 聚合字段
        ... n_fail = n_attempt-n_valid; wall_median/iqr; cer_median;
           cell_success_rate=n_valid/n_attempt; trunc_rate; unstable; err...

def run(cell, worker):
    try:
        while True:
            if cell.fatal: break                       # 异常置位也走这
            if cell.n_attempt >= cell.max_attempts: break
            cell.n_attempt_pre()                       # 预增（attempt 占位）
            try:    rep = worker.infer(timeout=1800)
            except CellFatal as e:  cell.fatal = e.kind;  break
            except WorkerFatal as e: respawn_or_mark(e)   # §7
            cell.absorb(rep)
            if extension_gate(cell): cell.max_attempts = 12      # R2-10 语义见 2.2
            if done_ok(cell): break
    finally:
        cell.finish()             # 2.2 判定树：唯一出口顺序
        save_raw(cell); validate_soft(cell)   # F-05

2.2 四收尾判定树（R2-10：顺序即正确性）

顺序条件结果说明
①median(walls) ≤ 0failed + err=median_le_0（报错留痕）提到分级之前（R2-10 修复：4-5 valid+median≤0 不得走 partial）
②fatal 非空failed + err_kindCellFatal/超预算 WorkerFatal
③n_valid < 4failed含 0 valid 全失败
④4 ≤ n_valid < 6partial（进分母、不进名次、单列）G1 强制 ranking_eligible=false
⑤n_valid ≥ 6 且 IQR/median ≤ 10%complete达标
⑥n_attempt = 12 且 n_valid ≥ 6 且 IQR > 10%complete + unstable=true（只报分布不排名）unstable 语义冻结：attempt 硬终止口径（与 done 定义同句，写入规格）；6valid/6fail 的 12attempt 场景不判 unstable（n_valid≥6 已满足但 IQR 按 valid walls 算——单测⑤覆盖）

7. 进程与控制 v3

  • 单写者（R2-09）：runner 独占 control/task.json（state/seq/ack/lease/last_progress/updated_by）；心跳进程只写 control/heartbeat.json；外部 UI 只写 desired_state（经 API 落 task 的 desired 字段由 runner 收编）；任何写=tmp+rename；lease TTL 60s 由 runner 续（renewed_at）。
  • stale 双判据：heartbeat.json 超 15s 或 last_progress 超过当前 cell timeout → 查 owner_pid：死=stale 阻断，活=stalled 标记不判死。
  • load_events（R2-17）：session 记 initial/respawn 每次 load 的 wall+rss_after+ok、respawn_count；teardown 断言按最后一次 load 的 baseline。
  • worker：venv 子进程、NDJSON 专用 fd、握手 hello{protocol_v,engine,python,torch,transformers}、单飞、分块、respawn 预算 1 次/引擎/小时、进程纪律走 process_guard.py。
